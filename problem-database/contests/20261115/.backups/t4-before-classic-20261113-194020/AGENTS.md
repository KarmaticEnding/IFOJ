# 本场比赛的造题约定

本文件适用于 20261114 整个工程。沿用上一场的工程要求，不沿用其具体题目内容。

- 严格使用 tuack 工程格式和题面模板。优先检查本机工具及现有结构，不覆盖用户已有文件；必要修改先备份，并保留无关改动。
- 题目名称、题序、部分分以用户最新决定为准。当前 product (T1), span (T3); T2/T4 remain placeholders。
- 标准程序必须放在对应题目的 GPT/ 下，文件名为 <题目名>.cpp。先完成正确性验证，再生成数据；验证方式应包含有意义的暴力、独立算法或独立实现核对。
- 一般测试点的规模应接近该档上界，不附加未声明、可被低档算法利用的简化性质。覆盖题目边界、不同结构和错误算法，而不是只依赖随机输入。
- 给出题面展示样例；此外，每档部分分都须提供一份公开大样例，放入 down/。仅 sample_file 大样例注明“该样例满足测试点……的限制”；sample_text 展示样例不写这句话。
- 题面的数据范围表格不加分值列。实际评分配置必须准确对应用户给定的部分分。
- 数字使用 tuack 官方格式化：题面使用 args[...] .hn() 或 tools.hn()，JSON 表格使用适合 JSON 转义的 tools.js_hn()。不要把应格式化的大整数或科学计数法直接写死在表格中。
- 若题目需要 SPJ，正式评测 SPJ 与下发 SPJ 必须分别实现、不能是同一个程序；使用 Mike Mirzayanov 官方原版 testlib.h，记录来源和版本，不自行编写替代 testlib.h。普通唯一答案题无需 SPJ。
- 若题目需要离线可视化，按该题需求提供可独立打开的 HTML；不自动给每题添加可视化。
- 时限与内存应结合实测并遵循用户最新设置。完成后用 tuack 评测核对实际分数和样例结果，渲染题面并检查排版。评测与渲染串行执行。
- 不擅自提交、推送或发布比赛。
