# 子序列

改编自 Codeforces 1409F — Subsequences of Length Two：
https://codeforces.com/problemset/problem/1409/F
保留原题 n<=200、0<=k<=n 的范围和原任务，只输出最大数量，无需构造。

## 完整做法

先考虑 t 的两个字符相同，记为 a。设原串含 c 个 a，最多得到 q=min(n,c+k) 个 a，答案为 q(q-1)/2。

以下设 t[0]=a、t[1]=b 且 a!=b。

处理字符时，只需考虑保留原字符、改为 a、改为 b。如果最终某个被修改的字符仍在 {a,b} 之外，把它还原既能节省修改次数，又不会减少答案：原字符若是 a 或 b，只会增加可选的下标对；原字符若也是其他字符，则计数不变。

令 f[i][j][c] 为处理前 i 个字符，恰好修改 j 个位置，且这 i 个位置中恰有 c 个 a 时，可以得到的最多 ab 子序列数。不可能状态初始化为 -1，f[0][0][0]=0。

枚举当前位置的最终字符 x，修改代价为 [x!=s[i+1]]：

- x=a：a 的个数加一，子序列数不变。
- x=b：每个已有的 a 都与当前位置构成一个新子序列，贡献 c。
- 其他字符：两者都不变，这种情况只需保留原字符。

答案是所有 j<=k、c<=n 的 f[n][j][c] 的最大值。

状态个数 O(n^2*k)，每个状态至多三个转移。时间 O(n^2*k)，滚动数组空间 O(n*k)。答案至多 n(n-1)/2<=19900，int 足够。

正确性可对处理的前缀长度归纳。状态完整记录下一位置贡献所需的 a 数量；枚举覆盖所有可能有用的最终字符，且每个转移准确计算新增下标对和修改代价。因此每个状态保存其定义中的最优值，最终取预算以内的最大值即为答案。

## 六档部分分

共 20 个独立测试点，每点 5 分，分档为 10/10/15/10/20/35。

1. 点1--2，n<=12：每个位置枚举保留/a/b，时间 O(n*3^n)，增量维护计数可进一步减少常数。
2. 点3--4，k<=1：枚举修改位置及目标字符，每次线性统计，O(n^2)。
3. 点5--7，k<=2：枚举至多两个修改位置及目标字符，每次线性统计，O(n^3)。可用前后缀计数优化，但无需优化即可通过。
4. 点8--9，a=b：直接使用组合数公式。
5. 点10--13，a!=b 且 s 仅含 a,b：有独立的交换性质做法，见下文。
6. 点14--20：完整 DP。

## 二元串的独立做法

设原串有 B 个 b，原答案为 V。固定将 x 个原有 b 改为 a、将 y 个原有 a 改为 b。若两个原有 b 中，较早的一个保留、较晚的一个改成 a，把二者的最终字符交换，会增加 ab 的数量，且修改次数不变。因此可选择最早的 x 个 b。同理可选择最晚的 y 个 a。

按 1 起始的下标 p 计算，一次 b->a 的独立增益是 B-p，一次 a->b 的独立增益是 p-1-B。分别预处理这些最优位置的增益前缀和 GB[x]、GA[y]。

多个修改的共同作用为：每对 b->a 减少一次重复统计，每对 a->b 也减少一次重复统计，每对相反方向的修改补加一次贡献。因此总答案为

V+GB[x]+GA[y]-x(x-1)/2-y(y-1)/2+x*y。

枚举 x+y<=k，即可 O(n+k^2) 求解。公式对选中位置交错的情况也成立；两个相反方向修改的共同修正始终是 +1。

## 数据设计与独立验证

GPT/subsequence.cpp 是正向、按预算和 a 的个数记录最大答案的滚动 DP。
tools/oracle.cpp 使用不同的状态：反向扫描，记录右侧 b 的个数和已产生的子序列数，最小化修改次数，时间 O(n^4)。字符相同的情况也用独立计数 DP 核对。
小规模由 Python 枚举所有最终三类字符串（a、b、其他字符），并允许把 a/b 改成其他字符，检验只保留三个有效选择的结论。另有直接搜索与至多两次修改枚举程序。

tools/verification.json 记录生成前的 8578 组双 DP 对拍、运行时错误检查、三程序交叉测试、文件输入输出测试及源文件 SHA256。
tools/data-audit.json 记录每份数据的规模、字符集合、预算、饱和预算、答案、独立检查方式、错误算法输出及输入/答案 SHA256。

一般大点均取 n=200、k>2、t 的两个字符不同，并含第三种字符；每个点都需要利用第三种字符才能达到最优。预算小于将整串改为最优 a...ab...b 的最少修改次数。多个点同时卡住不同平局处理的最大即时收益贪心。二元串专档另含倒序、交替、随机和连续段结构。

完整数据包含小预算、中等预算和接近饱和但仍有约束的预算。生成器采用固定随机种子，可复现。公开大样例与正式数据使用不同种子。
